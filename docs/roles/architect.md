# ロール: アーキテクト（architect）

**見るところ**: 責務分担・方式の妥当性・再利用・拡張性。部品やシステムの境界が適切か、将来の変更に耐えるか

## レビューのしかた

1. `docs/review-checklists/<種別>-review.md` のうち、ロールが architect の観点を上から順に確かめる
2. 観点ごとに「無効となるケース」に当たらないかを先に確かめる
3. チェックリストに無いが、このロールとして問題だと思う点は check_id を **NEW** にして指摘する（後で観点の追加候補になる）
4. 他のロールの観点には踏み込まない（重複指摘を避ける）。気づいた場合は Q で他ロールに渡す
